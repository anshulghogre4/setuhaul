State 21 — Proposal refusals — two failures and one expected condition, told apart (stitch-prompts §11 error variants)

SNAPSHOT_DRIFT · role="alert"
The schedule changed after this proposal was calculated, so it can no longer be applied safely.

Never a blind retry of the stale proposal. One action, and it is the only safe one.

PARTIALLY_INFEASIBLE · role="alert"
This proposal can't be applied — SHP1017 no longer fits any dock in the window, and the proposal only applies as a whole.

No "apply what's still valid" fallback is offered, because none exists. The interface never implies a capability the engine does not have.

RUN_ALREADY_ACTIVE · role="status" · not a failure
A re-sequence is already running — you'll be notified when it's ready.

Inline, non-blocking, and deliberately not red. This is an expected condition, not a failure, and it must not read like one — informational blue, role="status", no retry button, no dismissal required (edge-cases.md §4).

Three outcomes that a lazier design would collapse into one "something went wrong". Two are genuine refusals and carry role="alert"; the third is a normal concurrency condition and carries role="status", which is the difference between interrupting a planner and informing one (accessibility-behaviour.md §Announcement politeness matrix, U82). Every one names a cause and a next action — and where there is only one safe next action, only one is offered.

The first two must never share an icon or copy. One message deliberately covers both 404 and out-of-scope — a distinct "exists, but not yours" would leak that it exists, which is a scope leak in a multi-tenant product (auth-and-scoping.md). It names the planner's actual scope so the dead end is navigable rather than mysterious. The maintenance state always states an estimated duration: a maintenance page that does not say how long reads as indefinite, and it tells the planner their work survived, because the fear in a capacity-committing system is a lost decision. Copy rules throughout: no "Oops", no "Something went wrong", no apology for a system rule, no exclamation marks, and on any failed write, "Nothing has changed." is mandatory (voice-and-tone.md).
