# Voice and tone

> The most load-bearing file in this folder. §7.2b makes state wording a graded correctness requirement,
> not a style preference. Decisions follow `../README.md` U32, U42, U47, U50.

## The governing rule

**Sentences that declare operational state are templated. The assistant writes the glue around them.**

§7.2b is explicit about why: if the four state sentences are produced by sampling, one unlucky generation
tells a driver their slot is "booked" when it is held for 90 seconds. That is a broken promise in the
business sense — not a wording nit.

So there are two registers in this product, and they must never blur:

| Register | Who writes it | Examples |
|---|---|---|
| **Declarative** — states what is operationally true | **Templated.** Reviewed, versioned, parameterised. | "Held for you until 11:42:30", "Confirmed — Dock D1", "That hold has lapsed" |
| **Conversational** — clarifies, explains, reassures | Generated by the assistant | "Does that mean arriving at 11:00, or another hour from where you are?" |

A generated sentence may **never** be the one that declares state. It may introduce a templated sentence,
follow it, or explain around it.

---

## Banned phrasings

These are prohibitions, not preferences.

| Never | Why |
|---|---|
| "Booked", "reserved", "you have", "secured" for anything below `CONFIRMED` | Implies commitment that does not exist |
| A bare "OK" / "Done" / "Got it" after a state change | Ambiguous about *what* is now true |
| Any operational time without its dock **and** its date | Option sets can span days; a bare time is a wrong-day booking waiting to happen |
| "Your slot" before `CONFIRMED` | Possessive implies ownership |
| Implying warehouse agreement when only a message was *sent* | The OM004 lesson — a FAILED email is not a confirmation, and neither is a delivered one |
| "Successfully" for anything that is still pending | — |
| Exclamation marks in declarative copy | A capacity system does not celebrate |
| Apologising for system rules | "Sorry, that dock can't take your weight" → state the rule, offer the alternative |

## The four state templates

Each answers three questions: **what is true now, what happens next, what must I do.**

### 1 · SHOWN — nothing is held

```
Three options are open right now at Jaipur DC.
Nothing is held yet — another driver can take any of these.

  [ Dock D4 · Tue 4 Aug · 12:15–13:30 · soonest        ]
  [ Dock D1 · Tue 4 Aug · 13:00–14:15 · no waiting     ]
  [ Dock D2 · Tue 4 Aug · 14:30–15:45 · most buffer    ]

Tap one to hold it for 90 seconds.
```

"Nothing is held yet" is mandatory and appears before the options, not after. A driver who taps without
reading must still not have been misled by what they skimmed.

### 2 · HELD — yours briefly, not requested

```
Dock D1 · Tue 4 Aug · 13:00–14:15 is held for you.
⏱ 1:24 remaining

This is not a booking yet. Send it to the warehouse to request it.

  [ Request this slot ]   [ Choose a different one ]
```

The countdown is part of the message, not chrome around it.

### 3 · PENDING_CONFIRMATION — requested, not agreed

```
Requested: Dock D1 · Tue 4 Aug · 13:00–14:15

The warehouse has not confirmed this yet. A planner will decide by 11:57.
If there's no decision by then, the slot is released and I'll find you fresh options.
```

Naming the deadline and what happens after it is what makes the wait tolerable. Never "we'll let you know."

### 4 · CONFIRMED — the only sentence that may say "confirmed"

```
✅ Confirmed — Dock D1 · Tue 4 Aug · 13:00–14:15, Jaipur DC
Reference APT-1042

You may check in from 12:00 (60 minutes early limit).
If you haven't checked in by 13:30, the appointment may be marked no-show.
```

Arrival guidance comes from RULE001 (60-min early limit) and RULE002 (30-min no-show grace) — **real
rules, never invented**. A confirmation without arrival instructions is where detention starts.

## Negative-path templates

§12.2 requires demonstrating what happens when an option changes or disappears. These eight are that
requirement. Every one names a cause and a next action (U32).

### `HOLD_LAPSED`
```
That hold has lapsed — Dock D1 · 13:00–14:15 is available to other drivers again.
Nothing has been lost; I can look again right now.

  [ Find options again ]
```

### `PENDING_EXPIRED`
```
No planner responded in time, so Dock D1 · 13:00–14:15 has been released.
This has been escalated to operations, and I can look for fresh options now.

  [ Find options again ]
```

### `SLOT_CONFLICT`
```
Another driver requested Dock D1 · 13:00–14:15 a moment before you.
That one's gone — here's what's open now.
```
Never blame the driver for being slow. State the fact, move immediately to alternatives.

### `OPTION_WITHDRAWN`
```
Dock D5 has just gone out of service, so the 18:00 option is no longer available.
The other two options are still open.
```
Plus the affected card greys and strikes through in place (U50).

### `NO_SAME_DAY_SLOT`
```
Nothing works at Jaipur DC today — the reefer dock is down for maintenance
until 22:00 and the site closes then. The earliest I can offer is tomorrow.

  [ Dock D5 · Wed 5 Aug · 06:00–07:15 ]
  [ Dock D5 · Wed 5 Aug · 07:30–08:45 ]

Nothing is held yet. If waiting overnight doesn't work, I'll bring in operations.

  [ That doesn't work — get help ]
```
The one negative-path message carrying good news underneath. Name the specific blocking reason, give dated
alternatives, offer the escalation route without making them ask.

### `NO_FEASIBLE_SLOT` → escalation
```
I can't find a workable slot for this load at Jaipur DC — the only reefer dock
is out of service past your arrival time, and there's nothing tomorrow either.

I've passed this to operations. Reference ESC-4471. Someone will contact you directly.
```
Always carry a reference and a promise of contact. An escalation without a reference feels like being
dropped.

### `HUMAN_JOINED` (U47)
```
─────────────────────────────────
  Neha from Operations has joined
─────────────────────────────────
```
A divider, not a bubble — it is an event, not a message. §7.4: silent takeover reads as the bot ignoring
them.

### `CONNECTION_LOST`
```
You're offline. I'll send this as soon as you're back.
```
Never lose a driver's typed message. Queue and retry.

## Refusal templates (U61)

A fifth family, distinct from the four above: **negative paths are things the system did to a driver;
refusals are things it declines to do for one.** §7.2 requires each name the specific rule and who can
act — left to generation, a refusal degrades into a vague apology, which is exactly the "sorry, that can't
be done" the banned-phrasings list already guards against for other contexts. Two of these five are
liability-adjacent (safety, off-manifest cargo) and are reviewed wording, not a template to riff on.

### "Just confirm it, don't wait for the warehouse"
```
Only a warehouse planner can confirm a slot — I can't skip that step.
I can flag your request as urgent so it's reviewed first.

  [ Flag as urgent ]
```

### "Book me the 7:30 even though I get there at 8"
```
7:30 won't work — your ETA is 8:00 and the unload needs to finish
before the slot closes. Here's what does fit your arrival time:

  [ Dock D2 · Tue 4 Aug · 08:15–09:30 ]
```
Names the specific failing invariant in plain language, never "that's not allowed."

### "I'm carrying something not on the manifest"
```
That's not something I can schedule around — it needs a person to look
at before anything else happens. I've flagged this to operations now.
```
No scheduling continues past this point. Reviewed wording — a contradiction between the manifest and the
load is exactly the kind of fact this assistant must never paper over with a booking.

### "My brakes are failing, should I keep driving?"
```
That's not a decision I can make for you. Please contact your carrier
and pull over safely if you're not already stopped.
Reference ESC-4471 has been raised with operations.
```
Always the first line, always this direct, always routes to a human immediately. Reviewed wording — this
is the one message in the entire product where getting the tone wrong has the highest possible cost.

### "Give me the slot that truck ahead of me has"
```
I can't move another driver's booking. Here's what's actually open
right now:

  [ Dock D1 · Tue 4 Aug · 13:00–14:15 ]
```
States the policy once, briefly, then moves straight to what *is* available — dwelling on the refusal
reads as scolding.

## Clarification copy

§13.1 counts driver clarification turns as a cost. **At most one question per turn**, and only for a field
that blocks the next engine call.

Offer the two readings rather than asking an open question:

| Situation | Ask | Never |
|---|---|---|
| "I am late by one hour" (LOW confidence) | "Does that mean arriving at 11:00, or another hour from where you are now?" | "How late are you?" |
| Repair time given, not arrival | "What time do you expect to reach the gate?" | Anything inviting arithmetic on repair duration |
| Two shipments, ambiguous | "The Kota load due 08:45, or the later Kota load due 18:00?" | "Which shipment ID?" |

**Use human descriptors, not identifiers.** A driver knows "the Kota load," not `SHP1004`. Reference
numbers may ride along in brackets; they may not be the question.

### Low-confidence ETA — frame risk as a choice

```
I can hold 11:00, but if that time is uncertain, the 12:15 window gives you
an hour of cushion and avoids a second reschedule.
```
Let the driver price their own risk. They are better placed to judge it than the system.

## Internal surfaces

Planners and gate officers get a different register — terse, factual, no reassurance.

| Driver-facing | Internal |
|---|---|
| "I'll find you fresh options" | "Released · re-ranked" |
| "The warehouse hasn't confirmed yet" | "Pending · 11:57" |
| "That hold has lapsed" | "Hold expired 09:41" |

**Condensed receipts are fragments, not sentences:**
```
CRITICAL · 70 min late · exact dock · 0 min wait
```
Middot-separated, ordered by decision weight. A planner reads this in under two seconds — a sentence would
cost five.

**Displacement warnings are the exception — they get full sentences**, because they describe harm to a
third party and must not be skimmed:
```
Confirming this delays SHP1009 to 19:45.
```

## Reject reason vocabulary (U42)

Five typed reasons. Each maps to a fixed driver-facing sentence, previewed before sending.

| Code | Driver sees |
|---|---|
| `CAPACITY` | "The warehouse couldn't fit this slot alongside the trucks already scheduled." |
| `RULE_VIOLATION` | "That slot isn't allowed for your load at this facility." |
| `PRIORITY_CONFLICT` | "A higher-priority load needed that dock time." |
| `SAFETY` | "Operations needs to review this before scheduling." |
| `DATA_CONFLICT` | "Some details don't match our records — operations is checking." |

Each is always followed by the alternatives, or by an escalation route if there are none. **A rejection is
never the last message in a thread.**

## Error and empty states (U32)

Every one names a cause and a next action. No bare spinners, no "something went wrong."

| Context | Copy |
|---|---|
| Empty planner queue | "No pending requests. New ones appear here automatically." |
| Empty carrier fleet | "No active shipments. Completed loads are under History." |
| Gate — truck not found | "No shipment matches that. Check the number, or search by driver name." |
| Load failure | "Couldn't load the queue. This is usually a connection problem. [Retry]" |
| Write failure | "That didn't save — nothing has changed. [Try again]" |

"Nothing has changed" on a failed write is essential. In a system where a click commits capacity, a user
must know a failure left no partial state.

## Mechanics

- **Second person for drivers** ("you"), first person for the assistant ("I'll find you options").
- **Never "we"** — ambiguous between the assistant, the warehouse and SetuHaul.
- **24-hour time throughout.** `13:00`, never `1:00 PM`. Freight runs on 24-hour clocks and AM/PM errors
  are real.
- **Dates as `Tue 4 Aug`** — weekday included, because "the 5th" means little to someone who has been
  driving for eleven hours.
- **Times are always facility-local (U64).** A dock opens at `06:00` in *that facility's* zone — that is
  the operationally meaningful number, and it is what every template above renders. The zone label
  (`IST`, etc.) is appended **only when it differs from the viewer's own zone**. Today, with all six
  facilities on `Asia/Kolkata`, the label never appears and no template needs a conditional branch written
  for it — it activates automatically the moment a facility or a viewer outside that zone exists. Never
  render a time in the *viewer's* zone: a driver reading a dock time translated into their own timezone
  is a missed appointment, not a convenience.
- **Sentence case everywhere** except `text-label` state chips, which are uppercase by design
  (`typography.md`).
- **Never use a shipment ID as the subject of a driver-facing sentence.** "Your Kota load," not "SHP1004."
