04 · Gate/yard kiosk — mockup

Every screen and state in stitch-prompts.md, at true device size

22 screen groups, 35 artboards, in stitch-prompts.md order. Two device contexts (U108): mounted gate-booth kiosk (1280×800, landscape-fixed) and handheld yard tablet (800×1280, portrait). One interaction model, one dominant button per screen (U110). Frames render at true device size, so every value below is the real value — nothing is scaled.

Density spacious — the only surface in the product that uses it (spacing-and-layout.md density table): row height 64px, cell padding 20/24px, card padding 24px, stack gap 16px, content padding 32px, and a 56px minimum tap target. That is physical, not aesthetic: a gloved fingertip’s contact area is larger than a bare one, so the 44px used on the driver PWA is not generous enough. WCAG 2.2 SC 2.5.8 (Minimum) is 24×24px at AA and SC 2.5.5 (Enhanced) is 44px at AAA — 56px exceeds both, deliberately and self-imposed (U30).

Light theme only. Both themes are specified at parity (U7) and light is the global default (U69), but color.md requires dark to carry a “hard to read outdoors” warning on the two field surfaces, so a dark artboard here would render a configuration officers are told not to use. No app shell — no icon rail, no top bar, no status bar, no facility switcher, and therefore no facility accent colour anywhere (U59/U40 confine that palette to the rail stripe and the switcher swatch, neither of which exists on this device). No idle timeout exists on this surface, so no session-expiry affordance renders.

Operational text is text-primary throughout. color.md’s field-condition rule is explicit: body text on the driver and gate surfaces uses text-primary only, and text-secondary is reserved for genuinely secondary content and never for anything operational. So the appointment line, carrier, fact lines and supporting instructions all render at #0F172A (17.9:1 on white). text-secondary appears only on shift-bar attribution, the two low-emphasis controls, and this sheet’s own captions. Hierarchy is carried by weight, size and family, per typography.md’s dense-view rule — not by fading, because fading is what glare destroys first.

5 · Search — multiple matches (yard tablet, portrait)

screens.md §2 · Flow 1.4. A plate shared across trips is unlikely but possible. Explicitly a list of rows, not a dropdown — a native picker is unusable with gloves. Every row is a single tap target of at least 64px and the full card width; the chevron is a direction cue and is never the target. Gloved accuracy comes from the row being large, not from hitting a small affordance. No radio buttons plus a Continue step: the row itself is the action. Times use an en dash, 24-hour clock, and always carry both the dock and the weekday date — a bare time here is a wrong-day booking.

E5.4 fix 2026-08-29 (R3). Measured across all 22 yard-tablet artboards, this was the one screen anchored to the top of the frame — card top at 129px against a 490–759px norm everywhere else, a 361–630px discrepancy. It was also the only yard screen with more than one tap target, and the one where a mis-tap has the worst outcome on the surface: recording a gate event against the wrong truck. The thumb-arc placement the rest of the file argues for was the one thing this screen did not do. Corrected to the same spacer-then-card-then-thumb-pad structure screens 7–10 already use. Found only by rendering — the markup was indistinguishable from every other screen.

13 · Primary action — state sheet (default / focus / pressed / submitting / inactive-offline)

This folder’s components.md §4 · foundations components.md §1, §18 · edge-cases.md #7 · U70, U84. A component sheet, not a screen. Submitting is the state most likely to be got wrong: the label never leaves. The spinner takes the leading-icon position and the width is frozen. Nothing appears at all for the first second of a request (U84’s latency bands) — an indicator that flashes for under a second is pure distraction. Inactive is not a faded disabled control. It keeps full-contrast text, stays focusable and tappable, and activating it surfaces the explanation rather than doing nothing: on a sun-washed outdoor screen a faded, unfocusable grey rectangle is indistinguishable from a rendering failure, and an officer who cannot tell why a button won’t respond is locked out just as thoroughly as one who cannot read the screen. Buttons are separated by 32px, not the 16px stack gap, so a gloved mis-tap lands on nothing rather than on the adjacent control.

“Try again — this won’t record it twice” is required copy, not reassurance filler: every action on this surface carries an idempotency key (U70), so retrying is genuinely safe and the officer is told so. “Nothing has changed” on a failed write is equally load-bearing — in a system where a tap commits capacity, an officer must know a failure left no partial state.

14 · Outcome — Gate-in recorded (gate-booth kiosk, landscape)

screens.md §4 · components.md §5 · Flow 3. The computed arrival_state (EARLY / ON_TIME / LATE) is surfaced rather than buried — an early truck may still have to wait. 17 · Outcome — Different dock (DOCK_MISMATCH, yard tablet, portrait)

screens.md §4 · components.md §5 · Flow 5. Not an error. The tool contract says it is “allowed, but recorded as a deviation” — the officer recorded what actually happened, which is exactly what they should have done. Danger framing here would train officers to under-report honest deviations. So: warning tone, no red anywhere (red means expiry, conflict, escalation), no X icon, no correction affordance, no “Are you sure?”, no “This may cause a delay”. Text uses amber-700, not amber-600 — the 600 step measures 3.2:1 on white and fails normal text; the 500/600 amber steps are border and UI only. Warning messages are not dismissible, so no X on the block. Non-visual: 300ms haptic on a rejected gate action does not fire here — nothing was rejected.

Deliberately not rendered

Flow 9 — End shift. It has no screen of its own. The low-emphasis “End shift” control is inline in every screen from 3 onward; activating it clears the session name and returns to screen 1 or 2. There is no confirmation modal — ending a shift has no destructive consequence, and this surface uses no confirmation modals at all. Rendering a separate artboard would invent a screen the spec does not have.

A dark-theme artboard for any screen above. Dark is specified at full parity product-wide, but screens.md states it is not the expected real-world state here and color.md requires dark to carry a “hard to read outdoors” warning on field surfaces. A dark kiosk artboard would be a polished rendering of a configuration officers are told not to use.

An orientation-blocked / rotate-your-device screen. spacing-and-layout.md’s breakpoint table calls for one (“Gate kiosk 1024–1366px, landscape locked… below range shows an orientation prompt”), but U108’s yard tablet is a portrait device, so the two cannot both be true. The table predates U108. Flagged, not resolved here — the 800×1280 portrait frame is a plausible 10“ tablet value, not a spec value.

Any session-expiry affordance. No idle timeout exists on this surface. The shift name is local device state that persists until “End shift” is pressed.

Open items this file re-flags rather than resolves

Dwell as “1h 22m” (screens 12, 16) is taken verbatim from edge-cases.md #6, but it conflicts with data-formatting.md’s “space between number and unit” rule, and no grammar for absolute compound durations is defined there — only countdowns (M:SS) and relative-time bands. Rendered as written; the format still needs a ruling.

Event-timestamp fact lines carry no date (screens 14, 15, 16, 19). The product-wide rule “never an operational time without its dock and its date” is applied in full to every appointment line, which is where a missing date is a wrong-day booking. Gate-in / gate-out / unload timestamps are records of when an event just occurred on this device, not offers of dock time, and the prompts specify them verbatim without a date. Rendered as specified; flagged as the one place the rule’s scope is being read narrowly rather than applied.

Type scale. spacing-and-layout.md says density changes padding and row height only, never type size, while this surface needs a larger scale for outdoor legibility and typography.md’s own accessibility section forbids anything below 14px here. This file uses 16px for supporting text with a hard 14px floor, following the surface-specific argument, since the outdoor-legibility case is the specific one. Also flagged in stitch-prompts.md’s judgement-call table (items 1 and 2).
