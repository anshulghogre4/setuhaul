States 3–13 below implement stitch-prompts.md in full and differ from it in four places, all recorded rather than silently reconciled: the sketch's top bar carries a settings gear (stitch-prompts.md flag #6 calls this mockup drift) and emoji glyphs rather than Lucide; its status chip reads PENDING rather than the mandatory unabbreviated PENDING CONFIRMATION (components.md §2); it merges Facility and Dock into one column where the spec has two; and its stat-tile value is 24px/700 where components.md §14 specifies text-h3 (16px/600). State 6a — Dashboard loading — per-section skeletons

Four independent calls, four sections resolving independently — never one page-level spinner. The shell never shows a loading state: top bar, rail, section headings and column headers render immediately and stay put, because what is loading is data, not the application. Blocks sit at the exact dimensions of the content they replace, so nothing jumps when they resolve. Opacity pulse only, 1600ms — the single looping animation permitted in this product, and static under prefers-reduced-motion. Nothing at all renders under 1s in flight. The sparkline slot gets no skeleton: it is secondary content.

State 8 — Dashboard empty — "nothing yet" (new carrier, no history at all)

Frame B of two, kept as a separate frame per U74 — same visual emptiness, opposite meaning, and showing the wrong one makes a working system look broken. Tone is neutral and informational, never reassuring: there is nothing yet to be reassured about. The on-time tile shows — with no sparkline and no delta — an unknown must render as an explicit dash, never as 0% and never as a blank. That is three distinct renderings (0, —, absent) that must never look alike. The inbox glyph reads "not started" where state 7's circle-check-big reads "you're done". The exceptions section is hidden entirely for this state — the prompt permits either that or an inbox block, and this mockup picks hiding and applies it consistently. No call to action anywhere: this surface is read-only and a carrier cannot create a shipment.

State 11 — Degradation — refresh failed, data is stale

One notice, not five. A page reporting a separate warning per region has stopped being informative. It uses warning tokens, never danger red — a page that looks like it is on fire when the real problem is "these numbers are 40 seconds old" trains people to stop trusting red when it matters. The stale sections stay fully rendered and legible: not greyed, not overlaid, not blurred. role="status" and not a toast, because staleness is a persistent condition, not an event.

State 12 — shipment detail, read-only · four promise-state variants

One screen, four variants — the same chip component a planner sees, in its read-only consumption, with no affordance rendered beside it: no Confirm, Reject, Counter-offer, Reschedule or Escalate, not even greyed out. Nothing here has a hover state, a pointer cursor or an accent colour except the single ← Dashboard link. The dock-and-time line is mandatory in this exact shape — Jaipur · D5 · Tue 20 Aug · 13:00–14:15 — because an operational time never appears without its dock and its date: option sets span two days, and a bare time is a wrong-day arrival waiting to happen. 24-hour clock, weekday-bearing date, en dash for the range, facility local time never converted. History shows outcomes and driver-visible messages only — a planner's rejection note and an operations coordinator's internal remark are never-shown fields. Nothing on this screen explains why a contested interval went elsewhere; that would reveal another carrier's operations.

State 13 — Shipment detail — out-of-scope refusal

A stale bookmark, a forwarded link, or a load reassigned to a different carrier upstream. The server refused the request; the client never received the shipment's data at all. The copy is exact and must not be rewritten: it says the shipment isn't in your fleet — not that it does not exist, was not found, was deleted, or belongs to someone else. That one sentence covers both the "genuinely does not exist" and the "exists but is out of scope" cases deliberately, so the screen cannot be used to probe for which shipments are real. No mono type on this screen and no shipment ID echoed back — repeating it invites the reading that the system looked it up and found something. No search box offering another route to the same disclosure, no "request access", no 404 numeral. The headline is the focus target on arrival and is announced assertively. The block sits directly on the page ground: no card, no shadow — this is a full-region state, not a component in a container.

What is absent from every frame above, on purpose. No benchmark line, no shaded "industry range", no percentile, no rank badge, no "you're 2nd in the queue", no facility utilisation figure, no "3 carriers affected" — and not even a count of anything outside this account, because aggregates leak individual facts. No facility switcher, filter or tabs: a carrier's fleet spans whatever warehouses it delivers to and is always shown whole, so facility is a value in a row and never a scope control. No coloured facility accent anywhere, and the rail's outer edge is a plain 1px border rather than the 4px facility stripe every other console carries. No action of any kind — this surface has no mutating tool in SOLUTION_DESIGN.md §7.5.6, so a control that appears Disabled would misrepresent it; scope-denied is always Hidden. No live updates, no auto-refresh, no "3 new" badges, no websocket indicator: refresh is manual, everywhere.
